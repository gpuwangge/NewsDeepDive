# 10/10/2026 [Cloudflare发布Clef-omni](https://news.aibase.com/zh/news/31537)
特邀评论员：Perplexity(Perplexity AI, Inc)  
责任编辑：Wangge  


## 新闻回顾

Cloudflare 于 10 月 9 日发布开放权重模型 Clef-omni，并上线 Workers AI。它基于 Qwen3-Omni-30B-A3B-Instruct 的混合专家架构（MoE，约 30B 总参数、3B 活跃参数），支持文本、图像、音频（WAV、MP3）与带声音的视频（MP4、WebM）。与聊天模型不同，它面向结构化决策：通过一次前向计算，为 Schema 中每个问题的允许选项输出概率，不生成自由文本。 

模型以 Apache-2.0 许可证发布，采用冻结底座、低秩适配器（LoRA）、标签平滑交叉熵与 Brier 分数校准训练。官方博客报告文本、图像请求中位延迟分别约 130 ms、150 ms，21 秒有声视频约 1.5 秒；但另一份官方更新日志给出了明显更低的数字，测量口径尚不明确。 

同期，Clef-flash 每百万输入 Token 价格从 $0.09 降至 $0.038，约降价 58%，但托管上下文从 64K 缩至 24K；Clef 则通过迁移至 SGLang 等服务优化，实现约 1.7～2.0 倍中位延迟加速，权重不变。 

## 技术分解

### Q1：它是新的通用大模型，还是多模态分类器？

更准确地说，它是建立在通用多模态底座上的 **决策模型**。

处理流程可以概括为：

```text
状态描述 + 图像/音频/视频 + 问题与候选选项
                      ↓
          多模态编码器 + Qwen Thinker
                      ↓
          Joint Schema Head 联合评分
                      ↓
        各问题的候选选项概率 / 结构化答案
```

它使用 Qwen 的理解主干与视觉、音频编码器，不使用语音生成组件。联合决策头通过两阶段注意力路由，将输入证据关联到候选选项与问题，再联合评分。模型支持 `noul`（真假）、`choice`（分类）和 `score`（有序评分）等问题类型。 

优势是省去逐 Token 生成与输出解析，适合审核、路由、告警分类和工具选择；局限是输出空间由调用者预先定义，不能替代开放式解释、内容创作或任意文本生成。 

### Q2：“原生视频输入”是否意味着不再抽帧？

不是。它省掉的是开发者手动搭建的转写、拆轨和模型串联流程，并不意味着模型直接理解压缩视频码流中的每一帧。

公开模型卡说明，视频文件默认按每秒 2 帧采样，并结合音轨处理；自托管仍需 `av` 等媒体解码依赖。因此，“完整视频输入”指可以提交完整视频文件，不代表逐帧无损理解。 

这也带来一个工程边界：默认采样可能遗漏短暂视觉事件。用于碰撞、设备异常或快速动作检测时，需要验证采样策略，而不能仅凭“支持 MP4”判断能力足够。

### Q3：与同系列及直接竞品相比，表现如何？

以下为 Cloudflare 公布的内部评测，不是独立第三方结论。不同指标不能横向混算；BFCL、家电模拟器为整例准确率，其他行分别采用 macro-F1 或准确率。 

| 比较项 | Clef-omni | Clef | Clef-flash | TypeSafe Jev |
|---|---:|---:|---:|---:|
| 托管价格：美元/百万输入 Token | 0.150 | 0.240 | 0.038 | 本次不列，未核验具体价格 |
| 托管上下文 | 64K | 64K | 24K | 本次未核验 |
| BFCL 工具调用：整例准确率 | 98.2% | 98.5% | 98.8% | 95.8% |
| BANKING77：macro-F1 | 94.8% | 94.2% | 90.9% | 79.7% |
| 家电模拟器：整例准确率 | 69.3% | 83.0% | 97.7% | 52.3% |
| When2Call：准确率 | 63.3% | 72.4% | 65.6% | 81.0% |
| 发票处理：完整动作准确率 | 60.2% | 64.7% | 57.1% | 61.8% |

价格、上下文来自官方更新日志；性能来自模型卡。 

关键结论：

- 多模态支持不等于决策能力全面升级。Clef-omni 在银行意图分类上领先，但家电模拟器明显落后于 Clef-flash。 
- Jev 在 When2Call 上领先，说明“是否应该调用工具”仍是 Cloudflare 模型的相对弱项。 
- 发票处理完整动作准确率仅 60.2%，不支持直接推导出“可放心全自动执行复杂业务流程”。 
- 公布的主要表格没有系统展示音视频决策的专门评测；视频处理速度不能替代视频理解准确率证据。 

### Q4：130 ms 和 1.5 秒可靠吗？

只能作为官方报告值，不能直接视为生产 SLA。两份官方材料存在实质差异：

| 请求类型 | 官方博客 | 官方更新日志 |
|---|---:|---:|
| 文本 | 中位约 130 ms | 约 20 ms |
| 图像 | 中位约 150 ms | 图像或音频低于 100 ms |
| 21 秒有声视频 | 约 1.5 秒 | 约 300 ms |

两份材料没有充分解释上述差异，不能擅自归因为“网络耗时”或“纯推理耗时”。原新闻采用的是博客口径。 

实际选型应统一输入长度、媒体分辨率、上传耗时、并发量及硬件，再比较端到端 P50/P95。对于视频，1.5 秒评分还不意味着从开始录制起 1.5 秒即可完成判断。

### Q5：开放权重是否意味着容易在本地部署？

不一定。模型卡的 BF16 示例在单张 H200 上测试，理解主干约需 64 GB GPU 显存；3B 活跃参数并不等于只需存储一个 3B 模型。MoE 降低每次计算参与的参数量，但不能据此忽略完整权重的驻留成本。 

还需要注意两点：

- 自托管应采用模型卡的 `load_release_model` 和联合决策头，而不是把它当普通聊天模型调用 `generate()`。 
- Clef 的 SGLang 加速不能直接套用到 Clef-omni：后者模型卡仍将 SGLang 支持标记为 “coming soon”。 

### Q6：不生成文本，是否就没有幻觉？

没有自由文本生成，确实减少了胡编解释和格式解析失败的空间；但模型仍可能选错答案、误读声音、漏看视频事件，或对错误判断给出高置信度。

Brier 分数校准属于训练目标，不是任意业务分布下的可靠性保证。模型卡中 Clef-omni 的 RAGTruth 幻觉识别 F1 为 42.0，而 Clef 为 79.4；这测量的是识别幻觉的能力，不是模型自身“幻觉率”，但足以提醒读者不能把“决策模型”当作可靠性标签。 

高风险业务应显式加入“证据不足”选项、拒绝执行阈值和人工复核，而不是强迫模型在不完整的候选集合里选择。

## 新闻分析

### Cloudflare：用专用模型扩大推理平台价值

- 利：基于既有 Qwen 底座进行后训练，而非从零训练通用模型；同时与 Workers AI、AI Gateway 集成，有利于把决策推理转化为平台使用量。 
- 利：兼容 Jev/SystemOne API，降低用户迁移成本；降价和开放权重共同推动试用。 
- 弊：价格优势部分来自服务规格收缩。虽然官方称仅 0.24% 请求超过 24K，但这是其现有流量统计，不能代表所有客户。 
- 弊：音视频质量证据不足、官方延迟数字不一致，会削弱“又快又可靠”的宣传说服力。 

### 阿里 Qwen：底座生态获得扩展，收益不等于直接收入

- 利：Cloudflare 的产品证明，Qwen3-Omni 不只适合多模态对话，还可作为结构化决策系统的基础，扩大底座的下游用途。 
- 弊：从商业分工看，终端 API、客户关系和推理服务收入主要由 Cloudflare 承接。开放底座扩大生态影响力，不自动等于阿里获得相应收入。

### TypeSafe / Jev：遭遇价格与兼容接口竞争，但并未全面落后

- 弊：Cloudflare 明确强调 Clef-flash 比 Jev 更便宜，并提供兼容接口，竞争同时发生在价格和迁移便利性上。 
- 利：Jev 在 When2Call、BRIGHT 等任务仍领先，说明市场不必只按模态数量或最低价格选型；业务准确率仍有差异化空间。 

### 开发者与企业：管线更简单，验证责任没有消失

单 API 整合音视频理解，降低了接入复杂度；Apache-2.0 权重也提供自托管选择。但 API 单价不是系统总成本：媒体会转换为输入 Token，自托管需要显存和运维，误判还可能带来复核或业务损失。 

原新闻准确转述了输入格式、底座、博客延迟和降价，但“全面开源”“完整保留核心理解能力”“更高性价比”等措辞偏宽。更严谨的表述应是：开放权重与推理代码、保留底座理解架构、扩展模态支持；是否更准确、更便宜，需要按具体工作负载验证。 

### 最后总结：算力、资本、幻觉

- 算力：核心收益来自跳过自回归输出、联合评分与服务优化；多模态编码、长输入和 MoE 权重驻留成本仍然存在。 
- 资本：这更像“开放底座后训练 + 托管推理变现”的产品策略，而非从零投入通用模型竞赛；Flash 降价也伴随上下文规格缩水。 
- 幻觉：输出约束解决的是格式与候选范围，不是真实性。衡量价值应看错误决策率、置信度校准和拒绝执行能力，而不是“是否生成长文本”。
