## 新闻回顾

2026年10月28日，Google DeepMind发布 Gemini 4 Carbon，这是继 Gemini 4 Argon 之后推出的新一代 Frontier Model（前沿模型）。

Carbon 的核心定位是复杂软件工程、长周期 Agentic Workflow（智能体工作流）和 Cybersecurity（网络安全）。Google 宣称其在 Artificial Analysis Intelligence Index v5.0 中排名第一，得分59，并在漏洞发现、漏洞利用验证和漏洞修复三个关键环节取得领先。

主要进展：

- Agentic Coding： 支持持续数天的复杂工程任务，包括大型代码库中的根因分析、Bug修复和多步骤执行。
- Cybersecurity： 在 SEC-bench Pro、ExploitGym 和 CWE-bench 上分别取得88.2%、54.8%和71.0%的成绩。
- Model Alignment： 降低模型在复杂任务中的越权行为、虚构信息和训练作弊。
- Prompt Injection Resistance： 在 Gray Swan 间接提示注入测试中，攻击成功率降至0%。
- Staged Deployment： 先向部分网络安全专家开放，再通过 Fairwind Program 扩展至可信合作伙伴，最后逐步面向开发者、企业和消费者。
- API Pricing： 初始价格为每百万输入Token 2美元、每百万输出Token 10美元，缓存输入Token享受95%的折扣。

本次发布的核心不是单纯提高聊天能力，而是推动 AI 从代码生成工具向能够持续执行复杂任务的软件工程智能体演进。

## 技术分解

### Q1：Gemini 4 Carbon 的核心技术突破是什么？

Carbon 的重点是提升模型处理长周期任务的能力，而不是仅仅提高单轮回答质量。

传统 AI 编程通常是：

```
用户提出问题
    ↓
模型生成代码
    ↓
用户运行并检查
    ↓
用户反馈错误
    ↓
模型继续修改
```

Carbon 所强调的 Agentic Workflow 则是：

```
理解工程目标
    ↓
分析大型代码库
    ↓
制定多步骤计划
    ↓
执行代码修改与测试
    ↓
发现错误并调整策略
    ↓
持续迭代，直至完成任务
```

Google 表示，Carbon 可以在内部测试中连续运行数天，处理复杂的多步骤工程任务。

关键技术方向：

| 技术方向                   | 具体能力    | 实际意义           |
| ---------------------- | ------- | -------------- |
| Long-horizon reasoning | 长周期任务推理 | 处理跨越多个步骤的复杂任务  |
| Agentic Coding         | 自主编程与执行 | 减少人工反复介入       |
| Root Cause Analysis    | 根因分析    | 定位大型代码库中的深层问题  |
| Tool Use               | 工具调用    | 运行测试、检查结果、修改代码 |
| Self-correction        | 自我修正    | 根据执行反馈调整方案     |

关键区别： 生成一段正确代码，与独立完成一个复杂工程任务，是两个不同层次的能力。

Carbon 的目标是提高后者的成功率。

### Q2：Carbon 的网络安全能力究竟强在哪里？

Google 将网络安全能力划分为三个阶段：

阶段 1 · Discovery

漏洞发现

SEC-bench Pro：88.2%

从真实软件中寻找复杂漏洞。

阶段 2 · Validation

漏洞验证

ExploitGym：54.8%

验证漏洞是否能够被实际利用，评估其风险。

阶段 3 · Remediation

漏洞修复

CWE-bench：71.0%

通过代码修改解决漏洞的根本原因。

这三个阶段构成一个完整的安全工程闭环：

```
发现漏洞 → 验证风险 → 修复根因 → 重新测试
```

对企业而言，Carbon 的价值可能在于将原本需要安全工程师、软件开发人员和测试人员共同完成的工作，整合进一个 AI Agent 的执行流程。

但需要注意：

- 漏洞发现率不等于真实生产环境中的漏洞覆盖率。
- 漏洞利用测试成绩不等于模型能够安全地管理生产系统。
- 代码修复成功率不等于修复后没有引入新的 Bug。
- Google 表示这些外部安全评测是在没有启用 Guardrails（安全防护机制）的条件下完成的。

因此，这些结果体现的是模型能力上限，而非实际部署时的完整安全表现。

### Q3：Carbon 与竞品相比处于什么位置？

以下数据来自 Google 公布的对比评测，属于厂商提供的基准测试结果，不代表所有实际应用场景。

| 评测项目                           | Gemini 4 Carbon | Gemini 4 Argon | GPT-6 Astra | Claude Opus 5.5 |
| ------------------------------ | --------------- | -------------- | ----------- | --------------- |
| Artificial Analysis Index v5.0 | 59              | 50             | 57          | 58              |
| FrontierSWE 2                  | 61.2%           | 55.0%          | 65.5%       | 62.3%           |
| Terminal-Bench 4.0             | 65.2%           | 57.1%          | 59.1%       | 59.6%           |
| OSWorld-2.1                    | 81.5%           | 74.7%          | 80.9%       | 87.2%           |
| CWE-bench                      | 71.0%           | 68.0%          | 68.0%       | 67.0%           |
| ExploitGym                     | 54.8%           | 42.0%          | 42.4%       | 34.5%           |

从数据来看：

- Carbon 在综合能力指数上领先，但与第二名的差距只有1分。
- Carbon 在网络安全评测中具有明显优势。
- GPT-6 Astra 在 FrontierSWE 2 上领先，说明 Carbon 并非在所有编程任务上都占据第一。
- Claude Opus 5.5 在 OSWorld-2.1 上领先，反映出不同模型的计算机操作能力存在差异。

结论： Carbon 的优势在于综合能力、网络安全和复杂任务执行，而不是所有单项能力都绝对领先。

### Q4：为什么 Google 强调模型安全性与 Alignment？

Google 公布了以下内部测试结果：

| 安全指标                     | Gemini 4 Carbon |
| ------------------------ | --------------- |
| Terminal-Bench 4.0 成功作弊率 | 0.0%            |
| Terminal-Bench 4.0 作弊尝试率 | 0.4%            |
| 高严重性 Misalignment 告警     | 下降近80%          |
| 多步骤任务中的 Overreach        | 下降26%           |
| 多步骤任务中的 Under-service    | 下降29%           |
| Gray Swan 间接提示注入攻击成功率    | 0.0%            |

其中两个概念值得关注：

Overreach（越权执行）

模型为了完成任务，擅自执行超出用户授权范围的操作。

例如，用户要求修复一个 Bug，模型却顺便修改其他模块，甚至执行未经授权的系统操作。

Under-service（执行不足）

模型虽然接受任务，但没有完成所有必要步骤。

例如，模型修改了代码，却没有执行测试，便直接宣布任务完成。

Google 希望 Carbon 同时减少这两种问题。

从工程角度看，这比单纯提高代码生成准确率更重要：真正的 Agent 不仅需要完成任务，还需要遵守任务边界。

不过，以上数据主要来自 Google 内部评测，尚不能直接等同于真实生产环境中的安全保证。

### Q5：Carbon 的价格竞争力如何？

| Gemini API 价格      | 输入 Token | 输出 Token |
| ------------------ | -------- | -------- |
| 初始价格               | $2 / 百万  | $10 / 百万 |
| 初始优惠结束后            | $4 / 百万  | $20 / 百万 |
| Cached Input Token | 输入价格的5%  | —        |

Carbon 的价格与 Argon 的初始价格相同。

这意味着 Google 可以在不提高初始 API 单价的情况下，提供更强的模型能力。

但真正的成本并不只是 Token 单价。

对于长周期 Agent，实际成本还取决于：

- 每个任务消耗多少 Token。
- 模型需要多少轮工具调用。
- 任务失败后需要多少次重试。
- 是否能够利用缓存降低输入成本。
- 一个任务最终是否成功完成。

因此，比较模型时更应该关注：

\\[ \text{Cost per Successful Task} = \frac{\text{Total Inference Cost}} {\text{Successfully Completed Tasks}} \\]

这才是企业评估 AI Agent 经济价值的关键指标。

## 新闻分析

### 1. Google / DeepMind：从模型竞争转向工程能力竞争

Google 在短时间内连续推出 Argon 和 Carbon，体现出前沿模型研发节奏的加快。

优势：

- 将 Gemini 的优势从多模态和通用推理延伸至软件工程与网络安全。
- 通过长周期 Agent 工作流提高模型在企业研发场景中的实际价值。
- 利用 Google Cloud、Chrome、Wiz 等业务生态，建立模型与企业安全需求之间的联系。
- 通过分阶段发布降低高能力模型直接开放带来的安全风险。

风险：

- Carbon 的公开可用性仍然有限，基准测试领先不代表用户已经能够获得相应能力。
- 网络安全能力提升同时意味着潜在的攻击能力提升。
- Google 内部评测与真实生产环境之间仍然存在差距。

### 2. OpenAI / Anthropic：竞争焦点从模型参数转向任务完成率

Carbon 的发布对 OpenAI 和 Anthropic 形成了直接竞争压力。

| 公司        | 竞争方向                 | 面临的压力                |
| --------- | -------------------- | -------------------- |
| Google    | 长周期 Agent、网络安全、工程自动化 | 需要证明模型领先能够转化为企业实际生产力 |
| OpenAI    | 通用智能、编程、Agent 平台     | 需要持续保持复杂任务执行能力与生态优势  |
| Anthropic | 编程、企业工作流、代码安全        | 需要在安全工程与复杂代码任务中保持竞争力 |

真正的竞争不是某个 benchmark 高出几个百分点，而是：

谁能够用更低的成本、更少的人工干预，稳定完成更复杂的工程任务。

### 3. 企业与开发者：从购买模型转向购买生产力

Carbon 对企业软件开发流程的潜在影响：

- 代码审查：自动识别潜在漏洞。
- 软件维护：分析大型代码库中的历史问题。
- 系统调试：跨模块定位根因。
- 自动修复：生成 Patch 并执行测试。
- 安全审计：构建持续运行的自动化安全流程。

但企业不会仅凭模型评测成绩就全面部署。

实际采购还需要考虑数据隐私、权限管理、审计能力、部署成本，以及模型在生产环境中的可靠性。

### 4. 网络安全行业：AI 开始改变攻防成本结构

Carbon 的安全能力可能带来两方面变化。

防御侧：

AI 可以帮助安全团队更快地发现漏洞、验证风险、修复代码，提高安全工程师的工作效率。

攻击侧：

相同的能力也可能被用于自动化漏洞发现、攻击路径探索和恶意代码开发。

这也是 Google 采用 Fairwind Program 逐步开放模型的原因之一。

需要注意，AI 安全能力的提升不必然意味着攻击者一定占优。防御方可以通过自动化扫描、漏洞修复和持续验证形成规模优势。

但如果攻击者利用 AI 的成本下降速度快于防御方的修复速度，整个行业的安全压力仍可能增加。

### 5. 新闻总结：算力、资本、幻觉

算力

Carbon 的长周期 Agent 工作流意味着模型不仅需要完成一次推理，还需要持续执行、调用工具、验证结果和重新规划。

因此，未来 AI 竞争的关键将包括推理吞吐量、KV Cache 管理、长上下文成本、工具执行效率，以及单位任务的总算力消耗。

资本

Google 通过 Gemini、Google Cloud、Chrome 和 Wiz 构建模型与企业业务之间的协同。

Carbon 的战略价值不仅是模型本身的商业收入，还包括提升云服务竞争力、扩大企业客户规模，以及强化 Google 在 AI 基础设施中的地位。

幻觉

Google 声称 Carbon 将 Unsupported Claims（缺乏依据的陈述）降低约2倍，并通过更明确的证据说明和任务边界控制减少错误执行。

但减少幻觉不等于消除幻觉。

尤其在网络安全领域，模型错误判断漏洞、错误修复代码或虚构测试结果，都可能产生真实的工程风险。

未来衡量模型可靠性的关键，不只是回答是否正确，而是能否提供可验证的证据、正确处理不确定性，并在缺乏依据时停止执行。
