# 11/05/2026 [Microsoft升级DirectX光追架构(RTX5080)](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

特邀评论员：Perplexity(Perplexity AI, Inc)  
责任编辑：Wangge  

## 新闻回顾

Wccftech 报道，测试者 Osvaldo Pinali Doederlein 使用微软 `D3D12RaytracingClusteredGeometry` 示例，对比传统底层加速结构（BLAS）重建与簇化几何（Clustered Geometry）：RTX 5080 从 1.4 FPS 提升至 310 FPS，约为原来的 221 倍；加速结构重建从 720 ms 缩短至 1.0 ms，相关内存从 4,716 MB 降至 267 MB。同一示例中，RX 9070 XT 开启该功能后达到 91 FPS，RTX 5080 约为其 3.4 倍。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

核心是**复用**：Clustered Geometry 降低物体级包围体层次结构（BVH）的构建成本；分区顶层加速结构（PTLAS）减少场景级更新开销。微软通过 DirectX Raytracing（DXR）与 Agility SDK 1.722 Preview 提供标准接口，将 NVIDIA RTX Mega Geometry 已采用的关键能力引入跨厂商开发路径；此次预览还包含间接加速结构构建（Indirect Acceleration Structure Builds）。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

报道还介绍了 NVIDIA 的 DirectX 12 森林示例：在 25 km² 场景中容纳 6,000 万株可独立动画的植物，结合实时路径追踪、动态植被、636 种可复用细分模板及随相机变化的细节管理。它展示的是技术扩展方向，并非上述 221 倍测试的同一负载。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

## 技术分解

### Q1：221 倍到底加速了什么？

主要加速的是“维护光追场景”，不是“发射光线后求交”。

| RTX 5080 指标 | 传统 BLAS 路径 | Clustered Geometry | 含义 |
|---|---:|---:|---|
| 帧率 | 1.4 FPS | 310 FPS | 示例整体帧率约为原来的 221 倍 |
| 加速结构重建 | 720 ms | 1.0 ms | 构建耗时降至约 1/720 |
| Ray Dispatch | 1.8 ms | 2.0 ms | 光线阶段反而略慢 |
| 加速结构内存 | 4,716 MB | 267 MB | 减少约 94.3% |

以上均为报道转述的示例测量值；内存指标仅指加速结构，不是整款应用的显存占用。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

这组数据说明，旧路径几乎被 BLAS 重建拖死。新路径移除主要瓶颈后，即使 Ray Dispatch 略有退步，总帧率仍能大幅上升。因此，不能把结果解释为 RT Core 求交吞吐提升了 221 倍。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

### Q2：Clustered Geometry 如何改变 BLAS 构建？

微软的结构关系可以简化为：

```text
三角形簇 → CLAS → Cluster BLAS → TLAS / PTLAS
```

CLAS 即 Cluster Level Acceleration Structure，每个最多包含 256 个三角形和 256 个顶点。Cluster BLAS 通过引用多个 CLAS 组成；多个 Cluster BLAS 可以共享同一个 CLAS，而顶层实例引用的是 BLAS，不是单个 CLAS。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

其价值在于把大规模构建任务拆成更小、可复用的单元：

- 几何没有变化时，保留已有簇结构。
- 几何动画、流式加载或 LOD 切换时，以更细粒度组织构建工作。
- 降低使用完整细节几何进行光追的成本，减少光追代理模型与光栅化画面之间的差异。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

这不是“动画几何从此不需要重建”。更准确的说法是：它改变了构建粒度和复用方式，避免反复承担大块结构的完整构建成本。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

### Q3：PTLAS 与 Clustered Geometry 是不是一回事？

不是，两者解决不同层级的问题，可以独立使用，也可以组合使用。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

| 技术 | 工作层级 | 主要解决的问题 |
|---|---|---|
| Clustered Geometry | 物体内部的几何与 BLAS | 高细节几何反复构建成本高 |
| PTLAS | 场景实例与顶层结构 | 少量实例变化，却需要处理大范围 TLAS |
| 间接加速结构构建 | 构建任务提交 | 允许构建输入来自 GPU 内存，减少 CPU 侧描述重建 |

这些能力共同推动更细粒度、GPU 驱动的加速结构管理。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/agilitysdk-1-620-retail-and-1-722-preview/)

PTLAS 也并非没有代价。微软另一项多米诺骨牌示例中，更新耗时从 2.88 ms 降至 0.79 ms，但追踪时间略有增加。评价时必须看“结构更新＋光线追踪”的总成本，而不是单看构建阶段。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

### Q4：RTX 5080 比 RX 9070 XT 快 3.4 倍，能代表游戏差距吗？

不能。它只代表这个示例、这条执行路径下的结果。

| 比较项 | RTX 5080 | RX 9070 XT |
|---|---:|---:|
| 传统 BLAS 路径 | 1.4 FPS | 1.7 FPS |
| Clustered Geometry 路径 | 310 FPS | 91 FPS |
| 各自开启后的帧率倍率 | 约 221 倍 | 约 54 倍 |
| 两卡开启后的相对性能 | 约 3.4 倍 | 1 倍 |

数据来自报道；倍率按其给出的帧率计算。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

需要保留三个边界：

1. 这是合成示例，不是商业游戏综合测试。
2. 示例缺乏 LOD，远处仍保留过高几何复杂度，放大了旧路径的负担。
3. 对照是示例的传统 BLAS 重建路径，不能代表商业引擎已经优化过的最佳实现。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

测试者将 NVIDIA 较低的结构内存占用部分归因于其长期积累的 BVH 压缩能力，但报道没有提供能单独隔离压缩、驱动和其他因素贡献的实验，因此这仍是解释，而非已完成的因果证明。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

### Q5：开发者现在能直接用吗？Vulkan 又是什么情况？

可以开始验证，但 DXR 相关能力仍处于预览阶段，并不是更新驱动后所有游戏自动受益。

| 厂商 | 微软列出的支持范围 |
|---|---|
| NVIDIA | 全部 RTX GPU |
| AMD | Radeon RX 9000 系列 |
| Intel | Arc B 系列、Core Ultra 200V 系列及 Series 3 |

这是此次 SDK 发布的支持范围，不等于各产品具有相同的性能、内存效率或驱动成熟度。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/agilitysdk-1-620-retail-and-1-722-preview/)

DXR 集成需要匹配的 Agility SDK 预览头文件与运行时、支持驱动，以及用于启用实验特性的 Windows 开发者模式；簇化几何相关 shader 内建功能涉及 Shader Model 6.10。报道指出 NVIDIA Game Ready 621.01 已提供支持，AMD 则提供开发者预览驱动。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

Vulkan 侧，NVIDIA 已提供 `VK_NV_cluster_acceleration_structure` 和 `VK_NV_partitioned_acceleration_structure`，以及动画簇、动态细分、连续 LOD 和流式加载示例。但这些是 NVIDIA 厂商扩展，不能与 DXR 的跨厂商标准接口混为一谈。 [developer.nvidia](https://developer.nvidia.com/blog/nvidia-rtx-mega-geometry-now-available-with-new-vulkan-samples/)

## 新闻分析

### NVIDIA：把先发实现优势转化为标准生态优势

有利之处是，微软标准接口降低了开发者采用类似技术的门槛，而 NVIDIA 已有 RTX Mega Geometry、Vulkan 示例和几何预处理工具积累，能够争取较早的集成与调优机会。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

限制也很明确：接口标准化不是 NVIDIA 独占。AMD、Intel 已进入支持范围；单个高倍率示例不足以证明其在所有动态几何、路径追踪或开放世界游戏中都保持同等优势。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

### AMD 与 Intel：获得共同入口，但实现质量仍决定竞争结果

标准接口让开发者不必只围绕某一家私有 API 构建功能，有利于其他厂商参与高细节动态光追生态。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

AMD 在这项测试中从 1.7 FPS 提升至 91 FPS，说明技术本身同样有价值；但与 RTX 5080 的差距也表明，“支持功能”和“高效实现功能”是两回事。Intel 没有出现在这组性能测试中，不能据此推断其表现。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

### 微软：统一开发路径，但预览接口不等于即刻普及

微软的收益是把物体级簇构建、场景级分区更新和 GPU 驱动提交纳入共同接口，减少引擎面对不同硬件时的接口碎片化。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

代价是应用仍需处理功能查询、硬件覆盖、预览运行时及兼容路径。微软明确支持多厂商，也意味着最终效果取决于各家驱动与实现，无法仅由 API 名称保证。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/clas-ptlas-preview/)

### 游戏与引擎开发者：价值可能先体现为“能画更多”，而非“帧率翻倍”

更便宜的结构维护，可以让开发者把预算用于更高密度植被、更多动态对象，以及更接近光栅化原始模型的光追几何。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)

但已有资产与渲染管线不会自动获益。官方提供簇构建、连续 LOD 和流式加载工具，本身就说明它涉及几何组织与资产流程，而不只是替换一个构建调用。工程上应同时评估预处理成本、运行时更新、显存峰值和完整帧耗时。 [developer.nvidia](https://developer.nvidia.com/blog/nvidia-rtx-mega-geometry-now-available-with-new-vulkan-samples/)

### 最后总结：算力、资本、幻觉

- 算力：真正的突破是减少重复的加速结构构建工作，让 GPU 将预算用于更多动态几何；不是光线求交能力凭空提升 221 倍。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)
- 资本：从产业竞争看，潜在价值在于工具链、驱动实现与引擎集成形成的长期优势。标准化扩大了可服务市场，也削弱了私有接口的排他性；单个示例尚不足以推导显卡销量或公司收益。 [devblogs.microsoft](https://devblogs.microsoft.com/directx/agilitysdk-1-620-retail-and-1-722-preview/)
- 幻觉：最容易误读的是把“示例帧率倍率”当作“游戏普遍倍率”、把“加速结构内存”当作“总显存”、把“API 支持”当作“性能一致”。这条新闻证明了特定瓶颈可以被大幅消除，没有证明所有光追负载都会获得相同收益。 [wccftech](https://wccftech.com/nvidia-rtx-5080-sees-over-220x-fps-boost-with-new-directx-raytracing-technology-outpaces-rx-9070-xt-by-3-4x/)
