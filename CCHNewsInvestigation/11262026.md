# 11/26/2026 [OpenClaw发布新版本](https://docs.openclaw.ai/releases/2026.11.10)
特邀评论员：Perplexity(Perplexity AI, Inc)  
责任编辑：Wangge  

## 新闻回顾

OpenClaw 发布 v2026.11.10。本次版本包含 7,671 个 PR、633 个直接提交和 349 名贡献者。

三大亮点:
- **Deep Research**:默认开启。便携引擎使用用户已有的模型和 Web 工具,Google 托管研究引擎为可选项。输出带引用的报告,来源冲突时并排展示引文,证据缺口标在 Unresolved 下。任务可在 Gateway 重启后恢复,报告保存 7 天。
- **Knowledge**:可选开启,配置为 `plugins.slots.memory = "knowledge"`。它把对话、会议(Granola)、笔记和文件整理成本地 Markdown 知识库,内容包括人物、项目、决策和摘录。Control UI 提供 explorer 和项目 Timeline,本地 Git checkpoint 保留修订历史,另有 scribes 定时更新和 shadow mode 自动召回。不影响现有 `memory-core` 数据。
- **Browser handoff**:遇到登录、2FA、CAPTCHA 或敏感表单时,点击 Take control 接管浏览器标签页,点击 Release control 归还。5 分钟无操作会自动归还。

其他更新:
- **安装与引导**:Quick Start 支持后台常驻 Gateway,API Key 保存时即时校验,新增 GitHub Copilot 和 NVIDIA Jetson 指南。
- **节点与部署**:新增 `openclaw node join`(OpenClaw ID 邀请加六位验证码),并修复 Kubernetes、Docker、Windows 安装问题。
- **Web UI**:工具调用时间线、Cmd+K 后台会话、`/fork`、Dashboards 画廊、Settings 重构、加泰罗尼亚语。
- **实验功能**:Agent Templates 和 OpenClaw ID 远程访问在 Labs 中,默认关闭。

## 技术分解

**Q1:Deep Research 与同类产品相比如何?**

| 维度 | OpenClaw Deep Research | OpenAI / Gemini Deep Research | Perplexity Deep Research |
|---|---|---|---|
| 运行位置 | 自托管 Gateway | 云端 | 云端 |
| 模型 | 用户自选,可用本地模型 | 厂商固定 | 厂商固定 |
| 数据源 | Web 加本地文件或 URL | Web 加部分连接器 | Web 加文件 |
| 冲突处理 | 并排引文加 Unresolved | 通常给综合结论 | 通常给综合结论 |
| 成本 | 自付模型和搜索 token | 订阅制 | 订阅制 |
| 质量上限 | 取决于所选模型和搜索工具 | 厂商调优 | 厂商调优 |

便携引擎的质量由用户配置决定,开箱即用的结果可能不如厂商调优的方案。页面没有给出任何基准评测。

**Q2:“显示冲突来源”能解决幻觉吗?**

只能缓解。并排引文让用户能核对来源,但引文是否被误摘、来源本身是否可靠,仍需要人判断。Unresolved 标记依赖模型自我识别缺口,这一步本身可能出错。

**Q3:Knowledge 与普通记忆(memory-core)有何不同?**

- 它把记忆结构化为人物、项目和决策,并保留摘录出处,每条结论可追溯。
- 修订、撤回和合并都保留历史,由本地 Git 保证。
- 数据存放在本地,可按 agent 隔离或共享。
- 隐私上有一个例外:shadow mode 的关键词评分会把消息和候选摘录发给配置的 Decision provider。“本地”不等于“不外发”。
- 多个 scribes 持续写入,知识库可能积累错误结论。修订可追溯,但不会自动判断对错。

**Q4:Browser handoff 的安全边界在哪里?**

- 接管期间自动点击和输入暂停,截图、快照和其他标签页仍可用。
- 私有 Chrome 设置和密码管理器不暴露给 agent。
- 自动归还的 5 分钟窗口有风险:用户中途离开后,agent 可能在已登录的会话上继续操作。
- 它也说明,agent 仍无法独立应对 CAPTCHA 和 2FA,这些仍要人工完成。

**Q5:这个版本的工程质量如何?**

7,671 个 PR 说明开发节奏极快。已列出的变更大多是修复:安装器卡死、UI 抖动、状态丢失、Kubernetes init 容器误报成功。这说明产品面广、边角问题多。很多 PR 来自少数高频贡献者(如 @vyctorbrzezowski、@steipete),核心维护者的集中度较高。Agent Templates 引入 ClawHub 包安装,会带来供应链风险。页面提到模板页有安全和版本信息栏,但没有说明具体审核机制。

## 新闻分析

**项目维护者 / OpenClaw**
- 利:一个版本同时补齐研究、记忆、人机协作三块短板,产品形态更接近完整的个人 agent 平台。自托管加可选云引擎,兼顾灵活性和易用性。
- 弊:功能面过宽,稳定性和安全面压力大。默认开启的 Deep Research 会消耗用户的 token 和搜索额度。

**社区贡献者**
- 利:贡献可见,署名清晰,生态参与感强。
- 弊:项目依赖少数核心人员,新人贡献容易被淹没在高频 PR 中。

**用户(个人 / 开发者)**
- 利:数据主权、模型自选、成本自控,可接本地模型。
- 弊:要自己负责配置、运维和安全。输出质量不稳定,没有厂商的 SLA。

**Google(可选托管研究引擎)**
- 利:通过插件进入开源 agent 生态,增加其研究服务的调用量。
- 弊:在这个生态里只是可选项,默认引擎是模型无关的。

**云端 Deep Research 厂商(OpenAI、Perplexity 等)**
- 利:开源默认功能证明了这类能力有真实需求。
- 弊:“自带模型、自带搜索”的免费替代品会压低其定价空间。

### 算力、资本、幻觉

- **算力**:Deep Research 是长时间多步任务,耗费大量推理和搜索调用。成本由用户的模型账户承担,算力不再集中在平台手里。Jetson 和本地模型的指引说明,边缘推理正在成为可选项。
- **资本**:开源项目在 PR 数量上领先,但商业化路径没有在页面中体现。云厂商靠订阅回收算力成本,开源方靠生态和入口卡位,谁来为长期维护和安全审计付费尚不明确。
- **幻觉**:并排引文、Unresolved 和可追溯的 Knowledge 是在流程上约束幻觉,不是消除。长期记忆写错后会被反复召回,风险反而被放大。最终的核验责任仍在用户身上。
