# 11/17/2026 [Alibaba发布Qwen4-Max](https://siliconangle.com/2026/11/16/alibaba-launches-qwen4-max-with-training-attention-optimizations/)
特邀评论员：Perplexity(Perplexity AI, Inc)  
责任编辑：Wangge  

## 新闻回顾

阿里巴巴发布旗舰大语言模型 Qwen4-Max，采用 Qwen4 架构，重点优化训练效率、注意力计算与任务 Token 消耗，已通过阿里云提供服务。报道披露的主要信息如下： [siliconangle](https://siliconangle.com/2026/11/16/alibaba-launches-qwen4-max-with-training-attention-optimizations/)

| 项目 | 核心内容 |
|---|---|
| 模型规模 | 主干网络拥有 2.4 万亿参数，每次计算激活约 710 亿参数；另有 3280 亿 N-gram 参数 |
| N-gram 参数 | 报道将其描述为类似缓存的机制，用于减少重复计算 |
| 残差连接 | 从传统单通道扩展为四通道，并通过门控调节信息传递 |
| Gated DeltaNet | 降低处理长提示词所需的硬件资源 |
| QSA | 跳过回答问题时不需要处理的部分数据，进一步减少计算 |
| 效率表现 | 相比 Qwen3.8-Max，内部知识工作测试得分提高，Token 使用量最多减少 35%；Terminal-Bench 4.0 编程测试中最多减少 49% |
| 开源计划 | 计划开放采用相关技术的小型模型；同时开源 Qwen-Live-Delivery-Plugin |
| 交付方式 | 插件支持先交付初稿，再持续改进，用户可在过程中提供反馈 |

上述数字来自报道转述的厂商测试，不能直接视为独立验证的性能结论。

## 技术分解

### Q1：2.4 万亿参数、只激活 710 亿，意味着什么？

需要区分模型容量与单次计算量：

- 总参数决定需要存储、加载和部署的权重规模。
- 激活参数更接近每次计算实际调用的模型规模。
- 两者之比约为 3%，但不意味着显存需求或运行成本也只有稠密模型的 3%。

这种“总参数大、激活参数少”的设计体现了稀疏激活思路。不过，报道未披露专家数量、路由方式和跨设备通信开销，不能据此完整还原模型架构。

对 GPU 部署而言，重点不只是算术吞吐量，还包括权重驻留、访存、负载均衡和设备间通信。减少激活计算，不等于消除部署大模型的基础设施门槛。

### Q2：3280 亿 N-gram 参数就是 KV Cache 吗？

不能这样理解。

报道将其比喻为缓存，强调复用重复模式、减少重复计算，但没有提供具体实现。不能据此认定它缓存的是完整计算结果，也不能把它与推理阶段保存注意力键值状态的 KV Cache 混为一谈。

值得关注的是：模型尝试用额外的存储容量，换取部分计算节省。收益取决于查找与读取这些参数的成本，是否低于原本需要执行的计算。

### Q3：四通道门控残差连接为什么有价值？

残差连接提供跨层的信息路径，也有助于梯度传播。新闻用“梯度跳过部分层”解释这一机制，但不应将其理解为模型可以任意省略这些层的前向计算。

从单通道扩展为四通道，再引入门控，意味着模型可以更灵活地组合、传递不同路径的信息。

潜在收益是改善深层网络的优化与训练稳定性；但报道未给出消融实验，无法判断质量提升中有多少来自该设计，也无法量化新增通道的开销。

### Q4：Gated DeltaNet 与 QSA 是否在解决同一个问题？

两者都指向注意力计算效率，但报道描述的着力点不同：

| 技术 | 报道描述的作用 | 仍需验证的问题 |
|---|---|---|
| Gated DeltaNet | 降低长提示词处理的硬件需求 | 长距离信息保留与精确检索能力是否受影响？ |
| QSA | 跳过与当前回答无关的数据 | 如何选择要跳过的数据？会不会遗漏低显著性但关键的信息？ |

可以将其理解为减少长上下文处理负担的两条路径，但不能仅凭报道断言二者如何混合、应用于哪些层，或具有怎样的精确复杂度。

对代码仓库分析、长文档问答等任务，关键不只是“能处理多长”，还包括能否准确找出埋在上下文中的少量关键线索。

### Q5：Token 最多减少 49%，是否意味着费用减半？

不意味着。

| 比较维度 | Qwen4-Max 相对 Qwen3.8-Max | 解读边界 |
|---|---|---|
| 内部知识工作测试 | 得分更高，Token 最多减少 35% | 未披露完整任务分布、绝对分数与平均节省幅度 |
| Terminal-Bench 4.0 | Token 最多减少 49% | 未给出完整成功率、执行耗时与工具调用成本 |
| 用户实际费用 | 报道称成本更低 | 缺少价格表及同等任务质量下的账单对比 |
| 外部竞品表现 | 未提供可比数据 | 无法据此建立跨厂商排名 |

更少的 Token 可能来自更高效的推理，也可能来自更简短的输出。只有在任务成功率不下降、测试条件一致时，节省才更有说服力。

实际成本还取决于 Token 单价、工具调用、重试次数和执行时间。“最多减少”也不等于典型任务的平均收益。

### Q6：Qwen-Live-Delivery-Plugin 是速度提升，还是交互方式变化？

首先是交互方式变化。

它把“等待最终结果”改成“先看初稿，再持续修订”，并允许用户中途纠正方向。其直接价值是缩短首次可用结果的等待时间，减少模型沿错误方向持续工作的浪费。

但初稿更快出现，不代表最终任务更快完成。还需要考察总完成时间、修改次数，以及用户为审阅半成品付出的精力。

## 新闻分析

### 阿里巴巴：把竞争重点从参数规模转向任务经济性

有利之处：

- 通过训练、注意力和输出效率的组合优化，争取降低提供模型服务的成本。
- 将旗舰模型接入阿里云，有助于把模型能力转化为云服务需求。
- 小模型开源计划与交互插件，有助于吸引开发者进入其工具生态。

需要承担的代价：

- 巨大的总参数与额外 N-gram 参数仍意味着可观的存储和部署负担。
- 若缺少价格、独立测试和技术细节，外界难以判断收益是否可迁移到实际业务。
- 计划开源小模型，不等于 Qwen4-Max 本身开放权重；生态开放程度仍需分别看待。

### 企业用户与开发者：更值得测试，但不能只看 Token

主要吸引力是长任务中可能更低的消耗，以及能提前审阅、纠偏的交付方式。

采购或接入时，更有意义的指标应是“每个成功完成任务的总成本”，而不是单独比较每百万 Token 的价格。还应加入成功率、长上下文遗漏率、工具调用失败率和人工复核时间。

此外，旗舰服务与未来的小型开放模型不能默认具有相同能力，私有化部署方案需要单独评估。

### 其他模型厂商与算力供应商：效率压力上升，硬件需求未必下降

对其他模型厂商，这则新闻提出的竞争标准是：不仅要答得好，还要用更少资源完成任务。但现有材料不足以证明 Qwen4-Max 已领先任何特定外部竞品。

对算力供应商，单任务计算下降可能减少部分资源消耗；另一方面，更大的权重规模、更低使用成本带来的调用增长，也可能增加存储、带宽和集群需求。不能从 Token 节省直接推导 GPU 需求下降。

### 最后看三个角度

- 算力：优化方向是减少重复计算和无效处理，而不是让超大模型“无需算力”。实际收益要同时看计算、显存、通信和任务成功率。
- 资本：阿里有机会把架构效率转化为云服务利润或价格竞争力，但报道没有披露训练投入、服务毛利或真实客户账单，商业回报尚不能量化。
- 幻觉：更少 Token、更高测试得分和更快初稿，都不等于事实错误更少。新闻未提供幻觉率证据，关键任务仍需来源核验与可执行结果验证。
