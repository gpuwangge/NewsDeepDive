# 09/30/2026 [DeepSeek开源Huawei昇腾基础组件](https://www.reuters.com/world/asia-pacific/deepseek-partners-with-huawei-develop-chip-programming-tools-reducing-reliance-2026-09-30/)
特邀评论员：DeepSeek(Hangzhou DeepSeek Ltd.)  
责任编辑：Wangge 

## 新闻回顾

DeepSeek 于 2026 年 9 月 30 日正式开源**面向华为昇腾算力平台的基础设施组件**，涵盖 **TileLang 高级语言编译工具**、**计算库**与**分布式通信库**。所有组件与 DeepSeek 此前**面向英伟达平台**的开源组件**一一对应**。

核心开源组件包括：**DeepGEMM**（通用矩阵运算）、**DeepEP**（大规模跨设备通信）、**TileKernels**（向量计算与访存算子）、**FlashMLA**（稀疏注意力算子，提升长上下文处理效率）、**DeepSelect**（高效数据筛选）。

TileLang 昇腾版本对**昇腾 Ascend C 底层指令**进行封装，提供高级语言编程方式且**不损失硬件性能**。DeepSeek 训练中每一个 TileLang 算子，在昇腾上均有对应的高性能实现。双方共同推进了基于**昇腾 950 的 128 卡超节点方案**，对计算与通信进行了深度优化。

## 技术分解

### Q1：TileLang 到底是什么？和 CUDA 什么关系？

**A**：TileLang 是 DeepSeek 主推的**高级语言编程工具**，定位是“编程更简单、同时达到硬件性能上限”。它首先在英伟达 CUDA 生态上验证成熟，承载了 DeepSeek V4 训练中大部分算子的实现，如今被移植到昇腾平台。

关键在于：TileLang 昇腾版本**封装了 Ascend C 底层指令**，让开发者可以用更高级的语言编写算子，而不必直接面对昇腾的底层编程接口。这是降低昇腾开发生态门槛的关键一步。

| 维度 | CUDA生态 | 昇腾生态（此前） | 昇腾生态（TileLang 开源后） |
|------|----------|------------------|----------------------------|
| 编程语言 | CUDA C++ | Ascend C（底层） | TileLang（高级）+ Ascend C（底层） |
| 学习曲线 | 中等 | 高 | 显著降低 |
| 算子迁移成本 | 基准 | 需重写 | 高级语言封装后大幅降低 |
| 通信库 | NCCL | HCCL | DeepEP（与英伟达版对应） |

### Q2：这次开源的组件，性能到底如何？

**A**：DeepSeek 官方表述是“多项关键测试用例中，计算与通信性能**已接近硬件上限**”。具体数据方面，DeepEP 在昇腾超节点上实测 **Dispatch 375 GB/s、Combine 347 GB/s** 的通信性能。

**注意点**：
- “接近硬件上限”是**厂商自述**，缺乏第三方独立基准验证；
- 这些测试基于**昇腾 950 超节点 + 128 卡方案**的特定配置，不代表通用场景；
- 推理侧的优化数据（如 TPOT=5ms、每卡吞吐 2469 tokens/s）**不包含 Serving 调度和框架负载均衡影响**，实际部署性能会有折扣。

### Q3：Ascend C 和 TileLang 是什么关系？昇腾的软件栈层级如何理解？

**A**：昇腾软件栈的分层逻辑是：

```
上层：PyTorch / MindSpore / TensorFlow
中层：TileLang（高级语言） → Ascend C（底层算子语言）
底层：CANN（异构计算架构） → 昇腾芯片
```

CANN 是昇腾的**异构计算架构**，向上支持多种 AI 框架，向下服务 AI 处理器与编程，是连接框架和芯片的“操作系统层”。Ascend C 是 CANN 体系内的**算子编程语言**，TileLang 则在其上再加一层高级抽象。

### Q4：为什么说“一一对应”这个表述很重要？

**A**：“一一对应”意味着 DeepSeek 的策略是**生态镜像**：在英伟达上有 DeepGEMM、DeepEP、FlashMLA，在昇腾上也有一套同名同功能的实现。开发者从 CUDA 迁移到昇腾时，**概念模型不变，只需换后端**。

这是对英伟达软件护城河最直接的攻击方式。CUDA 的护城河不仅在于性能，更在于**二十年来沉淀的默认起点地位**——新模型先在 CUDA 上调通，其他平台只能做“备选”。DeepSeek 的做法是在昇腾上复刻一整套平行生态，削弱这种默认惯性。

## 新闻分析

### DeepSeek 视角

**利**：开源基础设施组件是“建生态”的经典打法。通过将自身模型训练依赖的算子库开源，DeepSeek 在事实上成为**国产算力软件栈的定义者之一**。V4 训练已经跑在昇腾上，“每一个算子都有对应实现”意味着 DeepSeek 对昇腾的依赖已经**从适配层面下沉到开发工具层面**。

**弊**：开源基础设施不直接产生收入。DeepSeek 的商业模式仍然依赖模型 API 和可能的定制化服务。将核心工具链开源，等于**把差异化能力让渡给社区**，长期看可能削弱自身议价能力。

### 华为视角

**利**：华为获得了**顶级模型团队的全栈级背书**。此前昇腾的软件生态被诟病“好用但难开发”，TileLang 封装 Ascend C 直接回应了这个痛点。CANN 已开源 50 余个源码仓，加上 DeepSeek 贡献的高性能算子库，昇腾对开发者的吸引力显著提升。

**弊**：DeepSeek 的组件是**模型专用优化**，服务于 DeepSeek V4 的架构特征（如 MLA、MoE）。这固然能提升 DeepSeek 在昇腾上的表现，但**不一定泛化到其他模型**。如果开发者发现“为 DeepSeek 优化的库跑自家模型效果一般”，开源的价值会打折扣。

### 英伟达视角

**弊**：这是黄仁勋口中“灾难性打击”的**具体落地**。不是某一款芯片被替换，而是 **“CUDA 作为默认优化起点”这条规则被公开挑战**。当 DeepSeek 这样的顶级开源模型团队主动建设昇腾的全套工具链，CUDA 生态的自我强化循环出现了裂缝。

**利**：英伟达的硬件优势（Blackwell 旗舰单卡 FP16 约 2.5 PFLOPS vs 昇腾 910C 约 800 TFLOPS）仍然真实存在。且 DeepSeek 的训练规模仍远小于美国头部实验室，短期内对英伟达营收的直接影响有限。

### 开发者视角

**利**：多一套高性能、开源的基础设施组件，意味着**国产算力的迁移成本下降**。有 CUDA 经验的开发者可以用 TileLang 快速上手昇腾。

**弊**：昇腾生态的**工具链成熟度、调试体验、社区支持**仍与 CUDA 有差距。开源代码不等于好用代码，实际迁移中可能遇到文档缺失、边界情况未覆盖等问题。


### 算力 × 资本 × 幻觉

**算力**：这次开源的实质是**算力可用性的提升**——不是芯片性能的提升，而是**让昇腾芯片被更高效地使用**。TileLang + DeepGEMM + DeepEP 的组合，解决的是“昇腾能跑 DeepSeek 但开发成本高”的问题，而非“昇腾能不能跑”的问题。

**资本**：DeepSeek 在**免费赠送自己的软件资产**。这既是生态投资（换取昇腾平台的长期绑定），也是一种隐性的**战略对冲**——在中美技术脱钩背景下，确保自身有非 CUDA 的生存路径。华为则获得了无法用采购金额衡量的生态信用。

**幻觉**：“一一对应”的叙事容易让人以为**迁移是零成本的**。实际上，高性能算子库的移植需要深度理解硬件微架构，“接近硬件上限”的性能来自华为与 DeepSeek 团队的**紧密联合优化**，普通开发者拿到的开源代码，在自身场景中未必能达到同等效率。开源是起点，不是终点。
