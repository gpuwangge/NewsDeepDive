# 11/04/2026 [Microsoft升级DirectX光追架构(RX9070)](https://wccftech.com/amds-rx-9070-xt-sees-over-50x-fps-boost-and-nearly-90-lower-ray-tracing-memory-usage-with-new-directx-technology/)

## 新闻回顾

微软正在升级 DirectX Raytracing（DXR），通过 Clustered Geometry（簇化几何体）、Partitioned TLAS（分区顶层加速结构）和 GPU-based Acceleration Structure Build（GPU 加速结构构建）等技术，优化光线追踪中的几何数据组织、加速结构更新与显存消耗。

在 AMD Radeon RX 9070 XT 的相关测试中，新技术展现出超过50倍的帧率提升，以及接近90%的光追加速结构内存节省。

这次升级的核心不是增加 GPU 的计算单元，而是减少光追过程中重复构建、更新和存储几何数据的成本。微软将其视为自2018年 DXR 推出以来最重要的一次光追技术升级。

## 技术分解

### Q1：为什么传统光追会消耗大量显存？

硬件光追并不是直接对所有三角形进行暴力求交，而是通过加速结构（Acceleration Structure，AS）减少搜索范围。

主要包含两个层级：

| 结构   | 全称                                  | 功能                        |
| ---- | ----------------------------------- | ------------------------- |
| BLAS | Bottom-Level Acceleration Structure | 描述单个模型的几何体及其空间关系          |
| TLAS | Top-Level Acceleration Structure    | 描述场景中各个实例的位置、变换及其对应的 BLAS |

加速结构通常基于 Bounding Volume Hierarchy（BVH，包围体层次结构）。

对于静态场景，BLAS 可以构建一次并重复使用。

但对于动态场景，例如大量变形的植物、毛发、布料和角色模型，每帧都可能需要更新甚至重建 BLAS。

传统方案的瓶颈包括：

- 加速结构构建和更新消耗大量 GPU 时间。
- 高复杂度几何体需要占用大量显存。
- TLAS 更新可能涉及大量场景实例。
- CPU 提交、GPU 同步及资源管理增加额外开销。

因此，光追性能不仅取决于 GPU 的 Ray Tracing Core 数量，也取决于加速结构的组织方式与更新策略。

### Q2：Clustered Geometry 是什么？

Clustered Geometry 将复杂几何体划分为更小的几何簇（Geometry Clusters），每个簇最多包含256个三角形。

其核心思想是：不再把整个模型视为一个必须整体更新的对象，而是将几何数据划分为可以独立管理的局部单元。

传统方式：

```
复杂模型
   ↓
构建整个模型的 BLAS
   ↓
模型发生变化
   ↓
重新更新大量几何数据
```

Clustered Geometry：

```
复杂模型
   ↓
划分 Geometry Clusters
   ↓
复用未变化的 Cluster
   ↓
仅更新变化区域
```

主要收益：

- 减少重复构建加速结构的工作。
- 提高几何数据复用率。
- 降低光追加速结构的显存占用。
- 更适合高复杂度动态几何体。

但 Clustered Geometry 并不是免费优化。几何簇的构建、管理和临时存储同样需要资源，开发者需要权衡更新效率与额外的 Scratch Memory（临时工作内存）。

### Q3：Partitioned TLAS 是什么？

Partitioned TLAS 将场景的顶层加速结构划分为多个区域。

传统 TLAS：

```
整个场景
   ↓
一个大型 TLAS
   ↓
场景发生变化
   ↓
更新整个场景相关结构
```

Partitioned TLAS：

```
整个场景
   ├── Region A
   ├── Region B
   ├── Region C
   └── Region D
          ↓
    仅更新发生变化的区域
```

例如，一个开放世界游戏中，玩家只在城市的一个街区活动，远处的森林、山脉和其他建筑并不需要每帧都更新。

Partitioned TLAS 可以将场景更新工作限制在相关区域。

其价值在于降低动态场景中的更新成本，而不只是减少三角形数量。

### Q4：GPU-based Acceleration Structure Build 有什么意义？

传统加速结构构建可能涉及 CPU 侧的资源准备、命令提交以及 GPU 执行。

GPU-based AS Build 让 GPU 能够参与更多加速结构构建和更新工作。

其潜在收益包括：

- 减少 CPU 与 GPU 之间的交互。
- 降低动态几何体更新的 CPU 开销。
- 提高 GPU 工作调度的灵活性。
- 减少部分场景下的同步等待。

不过，GPU 构建并不意味着所有 AS Build 都会更快。具体效果仍取决于数据规模、构建算法、GPU 负载以及同步策略。

### Q5：50倍性能提升和90%显存节省，具体是什么数据？

微软测试的关键数据如下：

| 指标       | 传统方案           | 新技术方案          |
| -------- | -------------- | -------------- |
| GPU      | Radeon RX 9070 | Radeon RX 9070 |
| 帧率       | 1.2 FPS        | 79 FPS         |
| 加速结构内存   | 约7.5 GB        | 774 MB         |
| 加速结构构建时间 | 约788 ms        | 约3 ms          |

注：上述数据来自微软的测试结果，使用 RX 9070 测试，不是 RX 9070 XT。文章标题提及 RX 9070 XT，但具体测试平台应以微软原始测试为准。

计算结果：实际帧率提升约66倍，远超50倍。

显存节省：接近90%。

需要特别注意：这里的7.5 GB和774 MB指光追加速结构的内存消耗，而不是游戏整体 VRAM 占用。

同时，1.2 FPS到79 FPS是特定测试场景的结果，并不意味着游戏开启新技术后普遍可以获得50倍性能提升。

### Q6：这项技术与 NVIDIA RTX Mega Geometry 有什么关系？

两者解决的问题高度相似：降低高复杂度动态几何体的光追加速结构构建与更新成本。

| 对比     | DirectX Clustered Geometry | NVIDIA RTX Mega Geometry |
| ------ | -------------------------- | ------------------------ |
| 技术提供方  | Microsoft                  | NVIDIA                   |
| 技术定位   | DXR 几何体组织与更新机制             | NVIDIA 专有的光追几何优化技术       |
| 核心思路   | 几何簇化、局部更新                  | 优化复杂几何体的加速结构构建与更新        |
| 硬件范围   | 支持的 AMD、NVIDIA、Intel GPU   | NVIDIA RTX GPU           |
| API 生态 | DirectX Raytracing         | NVIDIA RTX 技术生态          |
| 目标场景   | 高复杂度动态几何体                  | 高复杂度动态几何体                |

这并不意味着 DirectX 的新技术完全复制了 RTX Mega Geometry。

更准确地说，两者在解决的问题和优化方向上存在重合，但具体数据结构、构建算法和硬件实现并不完全相同。

微软的优势是标准 API 的生态覆盖，而 NVIDIA 的优势是可以结合自家 GPU 架构进行深度优化。

### Q7：这项技术有什么限制？

需要关注四个问题：

1. 测试场景特殊性：测试中的传统方案效率可能极低，不能直接代表现代游戏的常规表现。
2. 临时内存开销：Clustered Geometry 可能需要更多 Scratch Memory，降低加速结构显存占用不代表总显存一定下降。
3. 开发者适配成本：游戏引擎需要调整几何数据组织、资源管理和更新逻辑。
4. 实际游戏收益未知：不同游戏的几何体复杂度、动态对象比例、光线数量和 GPU 瓶颈不同。

这项技术最值得关注的不是某个极端测试中的66倍，而是它是否能够让更多游戏在有限显存下实现高质量动态光追。

## 新闻分析

### 1. Microsoft：通过软件架构降低硬件门槛

微软的核心目标是让 DirectX 在光追领域继续保持跨厂商的 API 地位。

过去，NVIDIA 可以通过 RTX 专有技术构建竞争优势。微软现在将类似的优化方向纳入 DXR，意味着 AMD 和 Intel 也有机会通过统一 API 获得相关收益。

利：

- 推动 DirectX 光追生态发展。
- 减少游戏开发者对单一 GPU 厂商的依赖。
- 延长现有 GPU 的使用周期。
- 提高 DXR 相对于其他图形 API 的吸引力。

弊：

- 开发者仍需要进行引擎适配。
- 不同厂商的驱动和硬件实现可能导致性能差异。
- 微软需要承担 API 设计、兼容性与开发工具维护成本。

### 2. AMD：改善光追竞争力

AMD 长期以来在传统光栅化性能上具有竞争力，但在高负载硬件光追方面，NVIDIA 通常拥有更强的技术优势。

DirectX 新技术对 AMD 的意义在于：不需要单纯依靠增加 RT 硬件数量，也可以通过更高效的加速结构管理改善性能。

利：

- 提高 Radeon GPU 的光追效率。
- 让16 GB显存的 RX 9070 XT 有机会处理更复杂的场景。
- 降低对更高端 GPU 的依赖。
- 改善 AMD 在游戏开发者生态中的吸引力。

弊：

- 需要依赖微软的 DXR 生态。
- 仍需要优化自家驱动和 GPU 架构。
- 不能保证所有游戏都能获得相同收益。

### 3. NVIDIA：竞争优势从硬件扩展到软件生态

NVIDIA 已经通过 RTX、DLSS、OptiX、RTX Mega Geometry 等技术形成了相对完整的生态。

DirectX 新技术对 NVIDIA 来说既是机会，也是挑战。

利：

- RTX GPU 同样可能受益于 DXR 的通用优化。
- NVIDIA 可以继续利用自家硬件与软件结合的优势。
- 更高效的光追能够推动更复杂的游戏场景。

弊：

- 通用 DXR 优化可能缩小 NVIDIA 与 AMD 在部分光追场景中的性能差距。
- 游戏开发者对 NVIDIA 专有技术的依赖可能降低。
- 单纯依靠硬件性能优势的竞争方式受到挑战。

### 4. 游戏开发者：更高几何复杂度成为可能

游戏开发者可以使用更复杂的动态模型，而不必完全依赖静态几何体、简化模型或传统光栅化技术。

尤其是：

- 大量动态植被。
- 高精度角色模型。
- 毛发与布料。
- 大规模开放世界。
- 动态几何体 Path Tracing。

但开发者需要解决 Cluster 管理、Scratch Memory、GPU 同步和资源生命周期等工程问题。

技术能力提升，并不代表游戏开发成本自动降低。

### 算力、资本、幻觉

算力： 新技术并没有凭空增加 GPU 算力，而是减少无效的加速结构构建和更新工作。未来光追性能的竞争，将同时涉及 RT Core、显存带宽、BVH 算法和数据组织效率。

资本： 如果软件优化可以显著降低显存需求，消费者可能不必频繁升级更高显存的 GPU。对 AMD 而言，这是改善产品竞争力的机会；对 NVIDIA 而言，则需要继续通过硬件和软件生态维持优势。

幻觉： 50倍性能提升和90%显存节省属于特定测试中的极端结果。将其直接理解为所有游戏的性能提升，或者认为新技术可以让8 GB显存 GPU 普遍实现高端光追体验，都是错误的。真正的价值需要通过实际游戏、不同 GPU 和不同场景验证。
