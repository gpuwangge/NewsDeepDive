# 10/16/2026 [NVidia,Meta和Apple合作大模型本地运行](https://www.wsj.com/cio-journal/nvidia-meta-and-apple-unveil-new-open-models-501d4173)
特邀评论员：Perplexity(Perplexity AI, Inc)  
责任编辑：Wangge  

## 新闻回顾

英伟达于10月15日推出三款 Nemotron 系列开放模型，面向从数据中心到桌面的 AI Agent（智能体）部署：

- Nemotron 3.5 Super VL：1200亿参数的视觉语言模型，支持文档理解、工具调用和长期运行的多步骤任务。
- Nemotron 3.5 Bolt 74B-A9B 24GB：740亿总参数、约90亿激活参数的混合专家模型（MoE），采用原生2-bit量化，面向本地研究、浏览器操作和编程。
- Nemotron 3.5 Bolt E4B 4GB：面向语音、交互角色及物理智能体，计划10月23日发布。 

同期，Meta 发布开放权重模型 Muse Spark Open：8160亿总参数、每 token 激活约420亿参数，支持原生多模态、100万 token 上下文及智能体编程。苹果更新 MLX 框架，使其能够在多台搭载 M5 Ultra 的 Mac Studio 上运行。 

核心变化是：**开放权重**与本地推理正在成为企业部署智能体的另一条路径，但“可以下载”不等于“运行便宜”，也不等于完整开源。

## 技术分解

### Q1：这些产品如何对比？苹果是否也发布了自己的模型？

苹果在这次合作中主要提供硬件、MLX 框架及分布式推理优化，Muse Spark Open 的模型来自 Meta。两条路线的竞争点是部署平台与工作负载，不宜只按参数量排名。 

| 方案 | 参数与部署信息 | 主要用途 | 需要注意 |
|---|---|---|---|
| NVIDIA Super VL | 1200亿参数；覆盖企业服务器与本地系统 | 多模态文档、工具调用、持续运行的企业智能体 | 厂商强调任务效率，不能据此推断所有编程任务都领先 |
| NVIDIA Bolt 74B-A9B | 740亿总参数、约90亿激活；原生2-bit；24GB内存定位 | 本地浏览、研究、编程与调试 | 低比特压缩降低部署门槛，实际能力仍需按任务验证 |
| NVIDIA Bolt E4B | 4GB内存定位；10月23日发布 | 语音、交互角色、嵌入式与物理智能体 | 不能将其能力等同于大型推理模型 |
| Meta Muse Spark Open + Apple MLX | 8160亿总参数、420亿激活；100万 token 上下文；支持多台 Mac Studio | 大型代码库、多步骤智能体、本地多模态推理 | 高内存、多机配置仍是门槛，并非普通 Mac 即可运行 |

英伟达配置与定位来自其公告及同期报道；Meta、苹果配置来自双方技术资料。 

### Q2：MoE只激活部分参数，为什么仍需要这么多内存？

MoE减少的是每个 token 参与计算的参数量，不代表其他专家权重可以完全不存储。

以 Muse Spark Open 为例：

- 总参数为8160亿，激活参数约420亿。
- 苹果指出，仅 BF16 权重就需要超过1.6TB内存。
- Meta 给出的 NVFP4 量化配置是两台各512GB，或四台各256GB统一内存的 Mac Studio，总计1TB。 

因此，评估部署必须分开看：

- 激活参数：影响每步计算量。
- 总参数与精度：决定权重存储的主要规模。
- 上下文与并发：还会占用运行时内存。

同样，Bolt 的“24GB”不能直接理解为任何上下文长度、任何并发条件下，都能与其他应用无压力共存。应在实际运行配置中验证。

### Q3：多台Mac运行大模型，技术意义在哪里？

苹果将 MLX 张量并行、Thunderbolt 5 上的 RDMA，以及 M5 Ultra 的统一内存结合起来，让模型跨机器执行。官方展示中，四台 Mac Studio 运行 Muse Spark Open 可达到每秒超过36个 token。 

其意义不是“桌面设备全面取代数据中心”，而是让部分开发者获得本地运行超大模型的选择。

评估时仍要区分：

- 模型能否装入内存，与高并发吞吐是否划算，是两个问题。
- 单次生成速度，不等于复杂智能体的端到端完成速度。
- 多机互联能扩展容量，但也需要考虑通信与部署复杂度。

上述36 token/s是特定配置下的官方结果，不能直接外推为与任意 NVIDIA 系统的成本或性能结论。 

### Q4：“5倍更快”应该怎样理解？

英伟达公告使用了“同类模型中最高约5倍吞吐”的表述，并援引 Artificial Analysis Intelligence Index。这个结论具有模型分组和测试配置边界，不能概括成“所有企业任务都快5倍”。 

对实际项目，更值得测量的是：

| 指标 | 要回答的问题 |
|---|---|
| 任务成功率 | 是否真正完成需求，而非只生成合理文字？ |
| 端到端耗时 | 是否计入检索、工具调用、重试及人工修正？ |
| 每成功任务成本 | 推理更快之后，整体费用是否下降？ |
| 量化后质量 | 低比特版本是否增加错误与重试？ |

这是评估建议，而不是新闻已经证明的性能结论。

### Q5：开放权重是否等于开源、免费商用与安全？

三者不能画等号。

- 英伟达称 Super VL 同时提供权重、开放数据集和训练配方，支持企业后训练与私有部署。 
- Muse Spark Open 使用自定义 Muse Model License，包含署名展示等要求；同期报道也明确提到商业使用存在条件。采用前仍需审查具体许可证。 

本地部署能够减少将数据发送至外部模型服务的需要，但“数据不出云”和“输出正确”是不同问题。对于能调用工具的智能体，建议另设权限限制、沙箱、操作日志，以及高风险动作确认，不能把模型部署位置当成安全保证。

## 新闻分析

以下为基于产品定位与部署方式的推断，而非厂商披露的经营结果。

### 英伟达：用开放模型扩大硬件与软件生态

有利之处：

- 从企业多模态任务到4GB级边缘应用，覆盖更多硬件档位。
- 免费提供模型资源，可以降低开发者启动项目的门槛，再通过 GPU、部署工具与企业支持承接价值。
- NeMo 定制、NIM 服务和现有硬件形成完整部署路径。 

不利之处：

- 模型更高效，可能降低单个任务的算力需求；能否转化为更多总需求，仍取决于应用增长。
- 开放模型与跨平台工具也给开发者保留迁移空间，下载量不等于硬件收入。

### Meta：扩大模型影响力，同时保留商业边界

有利之处：

- 开放权重及对 MLX、vLLM、SGLang 等框架的支持，有利于吸引开发者、企业定制者和推理服务商。
- 与苹果合作，使其模型不只绑定云端 NVIDIA 部署路线。 

不利之处：

- 8160亿参数仍需要较重的部署资源，“开放”不代表广泛用户都能自行运行。
- 自定义许可证在保留商业控制的同时，也增加采用方的合规审查成本。 

Meta 的目标更像是扩大模型生态，而非单纯依靠每次 API 调用收费；但生态影响力能否覆盖训练与维护投入，新闻没有给出答案。

### 苹果：把统一内存优势转化为AI开发平台价值

有利之处：

- 不必独自训练同规模模型，也能通过 MLX 和硬件适配进入大型开放模型生态。
- 多机本地推理，为高内存 Mac Studio 提供新的专业用途。 

不利之处：

- 需要多台高内存设备，仍属于专业配置，不是大众消费级功能。
- 演示证明了可运行性，但没有证明大规模服务时的总拥有成本优于 GPU 服务器。

苹果争取的是本地 AI 工作站和开发者入口，而不是这次就正面替代数据中心。

### 企业与开发者：自主权增加，运维责任也增加

开放权重和后训练提供了更大的部署、定制及数据驻留选择。 

代价是企业需要自行承担模型评测、版本维护、许可证审查及智能体权限管理。对代码助手，可将编译和测试通过率作为验收标准；对财务、医疗或可执行操作，应提高审核门槛，而不是只看演示效果。

### 最后看三个维度

- 算力：MoE、低比特量化和多机统一内存降低了部分本地部署门槛，但总权重、上下文及并发仍决定实际资源需求。 
- 资本：商业价值可能从模型调用费，转向硬件、部署软件、定制和运维；免费权重并未消除这些成本。 
- 幻觉：本地化解决的是部署控制问题，不自动解决可靠性。验收应看可验证的任务结果，并限制错误输出触发真实操作的能力。
